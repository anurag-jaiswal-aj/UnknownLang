## Delivered Capabilities

### Core Implementation

- **EVAL, SYN, INF, CTRL answer-task generation** — Four category generators for syntax comprehension, expression evaluation, semantic inference, and control-flow reasoning
- **Deterministic generation** — From derivation seeds using `GenerationState` with seeded hash-based randomness
- **Provenance tracking** — Generator metadata (generator, version, derivation_seed, surface_profile)
- **Two-source verification (T5)** — Production engine + reference evaluator must agree on expected value

### Validation Gates

- **T7 (Canonical comparison)** — Pairs differ only in allowed variation fields per `_ALLOWED_DIFF`
- **T8 (Discriminating pairs)** — Semantic variations produce different expected values
- **T9 (Non-triviality)** — Expected value not present as literal in query or examples (AST-based extraction)
- **T10 (Chance floor)** — Probability limits enforced (≤100000, rejects negatives, booleans, floats)
- **T13 (Identifiability)** — INF surface operators uniquely determined by examples via `T13Identifiability.check()`
- **T1 (Schema validation)** — Required fields, version, unknown fields in `validate_task()`
- **T2 (Identity)** — Task ID computed from canonical JSON via `compute_task_id()`
- **T6 (Public/private separation)** — Hidden tests excluded from public view

### Infrastructure

- **Task schema** — Canonical `TaskRecord` and `TaskSetRecord` with SHA-256 identity
- **Public projection** — `project_public()` filters hidden tests, expected values, difficulty, protocol.role
- **Environment management** — Derivation from semantic configurations via `build_environment()`
- **Prompt templates** — Structured prompts with examples and query via `Prompt` dataclass

## Known Limitations

### T13 Generation-Time Enforcement

T13 identifiability is enforced ONLY during approved INF generation paths, not universally through `validate_task()`. This is intentional to avoid cross-category validation overhead.

### T6 Substring-Matching Limitation

T6 uses Python's `in` operator for substring matching between hidden test calls and public content. This has a theoretical false-positive risk when one expression is a substring of another (e.g., `"(add 1 2)"` in `"(mul 10 (add 1 2))"`). The risk is low because generators never create hidden tests in M2.5.

### Runtime Boundaries

- **No full process-level sandbox isolation** (T11 deferred)
- **No persistent cross-process environment resolution** (T3 deferred)
- **No prompt-based leakage lint** (T12 deferred)
