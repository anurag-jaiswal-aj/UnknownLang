## 2. Root Cause of Expected Value Extraction Bug

### Bug Description

`_extract_expected_value()` treated `Expected` objects as strings instead of extracting the inner value dict.

### Root Cause

```python
def _extract_expected_value(expected: Any) -> dict[str, Any]:
    if isinstance(expected, dict):
        return expected
    return {"kind": "other", "value": str(expected)}  # BUG
```

When `expected` is `Expected(value={'kind': 'int', 'value': 42})`:
- `isinstance(expected, dict)` returns False (it's a dataclass)
- Falls through to `str(expected)` → `"Expected(value={'kind': 'int', 'value': 42})"`
- Comparison fails: `{'kind': 'int', 'value': 42}` ≠ `"Expected(value={...})"`

### Fix

```python
def _extract_expected_value(expected: Any) -> dict[str, Any]:
    """Extract expected value in standard format.
    
    Handles both the Expected dataclass and serialized dict representations.
    """
    # Handle Expected dataclass
    if hasattr(expected, 'value') and isinstance(getattr(expected, 'value', None), dict):
        return expected.value
    
    # Handle serialized dict
    if isinstance(expected, dict):
        if 'kind' not in expected:
            raise ValueError(f"Expected value must have 'kind' field: {expected}")
        return expected
    
    # Invalid format
    raise ValueError(f"Invalid expected value format: {type(expected)} - {expected}")
```

## 5. Watchdog Architecture Decision

### Decision: Watchdog IS integrated into public evaluation path

### Justification

1. **Approved requirement per ADRs:** Subprocess watchdog is approved as a backstop for trusted-local execution
2. **Public evaluation uses watchdog:** `evaluate()` → `_execute_with_watchdog()` → `execute_with_watchdog()` → `subprocess.run(timeout=30.0)`
3. **Wall-clock timeout:** Provides boundary protection for runtime execution
4. **Subprocess isolation:** Worker process isolates execution from harness

### Current Architecture

The watchdog is an integral part of the public evaluation path:
- Uses `subprocess.run(timeout=30.0)` for wall-clock timeout
- Worker process executes `ExecutionEngine.execute(canonical_text, spec, surface_profile)`
- Returns `WatchdogResult` which is classified into failure categories
- Timeout results in `resource_limit` with detail `wall_clock`

### Future Integration

Program tasks (M2.9) will use the same watchdog infrastructure with appropriate execution context.
